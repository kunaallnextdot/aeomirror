# DEPLOYMENT — AEOMirror

Production topology and the exact steps to deploy AEOMirror.

## Topology

| Component | Platform | Domain |
|-----------|----------|--------|
| Frontend (Vite SPA) | Vercel | `https://aeomirror.com` |
| Backend API | Render (Docker web service) | `https://api.aeomirror.com` |
| Monitoring worker | Render (Docker worker) | — |
| Database | Render PostgreSQL 16 | internal |
| Cache / rate-limit / queue | Render Redis | internal |
| Error tracking | Sentry (optional) | — |

The frontend calls the API over HTTPS with a Bearer access token (in memory) and a
`SameSite=Strict`, `Secure`, `HttpOnly` refresh cookie.

## 1. Backend + worker + DB + Redis — Render

The repository ships a `render.yaml` blueprint (API web service, standalone worker,
PostgreSQL, Redis).

1. In Render, **New → Blueprint**, pick this repo. Render reads `render.yaml`.
2. Set the **secret** env vars (marked `sync: false`) in the dashboard for both the
   `aeomirror-api` and `aeomirror-worker` services:
   - `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRICE_PRO`
   - `RESEND_API_KEY`, `EMAIL_FROM` (e.g. `AEOMirror <hi@aeomirror.com>`)
   - `ADMIN_EMAILS` (comma-separated bootstrap admins)
   - `SENTRY_DSN` (optional), `ADMIN_TOKEN` (protects `/metrics`, `/debug/*`)
   - `JWT_SECRET` is auto-generated by Render (`generateValue: true`).
3. `DATABASE_URL` and `REDIS_URL` are wired automatically from the managed services.
4. Deploy. The API container runs `entrypoint.sh` → `alembic upgrade head` → uvicorn
   (2 workers). The worker container runs `python run_worker.py`.
5. Point `api.aeomirror.com` at the `aeomirror-api` service (Render → Custom Domain).

**Key production env** (defaults set by `render.yaml`):
`ENVIRONMENT=production`, `SCHEDULER_ENABLED=false` (web) / `true` (worker),
`ENABLE_HSTS=true`, `TRUST_PROXY=true`,
`CORS_ORIGINS=https://aeomirror.com,https://www.aeomirror.com`,
`APP_BASE_URL=https://aeomirror.com`.

In production the config validator **fails fast** unless `DATABASE_URL` (non-SQLite),
`REDIS_URL`, and `JWT_SECRET` are set.

## 2. Frontend — Vercel

1. **New Project** → import this repo → **Root Directory = `frontend`**. Vercel
   detects Vite and reads `frontend/vercel.json` (SPA rewrites, security headers, CSP,
   asset caching).
2. Environment variables (Production):
   - `VITE_API_URL=https://api.aeomirror.com`
   - `VITE_GA_ID` (GA4), `VITE_CLARITY_ID` (Clarity), `VITE_GSC_VERIFICATION`
     (Search Console) — all optional.
3. Add domains `aeomirror.com` + `www.aeomirror.com`.
4. Deploy. `public/robots.txt` and `public/sitemap.xml` are served at the root.

## 3. Stripe webhook

Create a webhook endpoint in Stripe → `https://api.aeomirror.com/billing/webhooks/stripe`,
subscribe to: `checkout.session.completed`, `invoice.paid`, `invoice.payment_failed`,
`customer.subscription.created|updated|deleted`, `charge.refunded`,
`charge.dispute.created`. Put the signing secret in `STRIPE_WEBHOOK_SECRET`.

Without a Stripe key the API runs in **dev checkout mode** (local completion page) —
never enable that in production; set the keys.

## 4. Post-deploy verification

```bash
curl https://api.aeomirror.com/healthz          # {"status":"ok",...}
curl -i https://api.aeomirror.com/readyz         # 200 when DB reachable
curl -H "X-Admin-Token: $ADMIN_TOKEN" https://api.aeomirror.com/metrics
```
Then run the smoke checklist in `RUNBOOK.md`.

## 5. CI/CD

`.github/workflows/ci.yml` runs backend lint + tests and the frontend production
build on every push/PR to `main`. Vercel and Render auto-deploy from `main` after CI
passes (their Git integrations).

## Local production-like stack

`docker compose up --build` runs Postgres + Redis + the API (migrations on start) +
the frontend, using **dev-only placeholder** credentials. Never commit real values.
